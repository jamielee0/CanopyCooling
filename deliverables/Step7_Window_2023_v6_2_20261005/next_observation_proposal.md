# Targeted next-observation proposal — not an execution authorization

The current limitation is independent date coverage within comparable month/time groups. Adding pixels or spatial bootstrap draws does not add days. Existing weather differences and incomplete sensor azimuth also limit interpretation. The synthetic assessment provides no basis for claiming that one tested interval method resolves these limitations.

## Priority order

1. **Review the existing effects within an explicitly recorded release scope.** The fixed-date Phoenix results and previous spatial/quadratic sensitivities are computed but sealed. Record Reza's numerical scale tolerance before the applicable coefficient display and scale ruling. A later margin must acknowledge prior releases. This review should determine which population/time comparison is worth pursuing; no effect-dependent choice has been made in this proposal.
2. **Specify the intended target and acceptable uncertainty.** Distinguish a comparison of selected dates, an expected contrast among similar dates, an exact clock-time contrast, and a general summer pattern. Set a practically meaningful difference and desired interval precision before planning acquisition counts. No arbitrary new minimum pass count is imposed here.
3. **Audit additional 2023 metadata in the current cities under a separate recorded scope.** For the existing Phoenix June/August target, additional June mornings, June afternoons and August afternoons directly address singleton arms; additional August mornings also improve replication. Preserve all sixteen baseline passes and keep any expanded comparison prospective. For Atlanta, the current windows contain only one June date per arm; July lacks morning representation. Define an Atlanta-specific target rather than copying Phoenix's weights.
4. **Evaluate complete alternative years only if the 2023 frame cannot support the target.** The recorded 2023 Phoenix catalogue audit found no July or September morning acquisition in the defined window, even before quality screening. Recheck catalogue provenance in any new metadata audit, but do not relax the time window or substitute other years silently. Other-year data require explicit scope, year/month comparisons and product/context consistency checks.
5. **Consider another city only if it provides a missing design condition.** City choice should be driven by time, canopy/context, footprint and independent-date support. Existing Phoenix and Atlanta distributions do not justify a simple city ranking. Additional-city thermal processing remains outside this proposal.

## What the metadata audit should return

For each candidate, retain acquisition identity, year/month, apparent solar time, exact products and QA, unique non-overlapping footprint, view-angle/azimuth availability, canopy/context support and linked meteorology. Report comparable and differing conditions without selecting dates on their cooling effects. Track repeated geography separately from repeated dates. Do not use a new cloud, canopy, rainfall or geometry cutoff without a prospective justification and record.

Before thermal processing, freeze the expanded sample, target weights, primary model, references, missingness handling and uncertainty procedure. Re-run calibration on that proposed independent-date schedule, including heterogeneous and correlated-day sensitivities. Candidate counts should follow the scientific target and precision criterion, not the number that makes a current contrast significant.

No new catalogue search, data download, city/year processing, coefficient display, external message or meeting is executed by this document. It is a reviewable specification for the next scope decision, with the current pilot and all historical packages preserved.
